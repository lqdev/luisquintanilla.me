# Draft AT Resource Graph staging

The first Resource Graph integration is a **local, opt-in projection** of the
existing `blogroll`, `podroll`, and `youtube` collection data. It does not
replace or alter the collection pages, RSS feeds, conventional OPML files, or
the existing AT Protocol tracks.

## Wire-compatible draft shape

`ResourceGraphStaging.fs` emits one JSON object per selected collection using
the standalone project's draft incubation lexicon:

```json
{
  "$type": "me.lqdev.resourcegraph.temp.bundle",
  "name": "Blogroll",
  "description": "Websites and blogs I follow regularly",
  "members": [
    {
      "position": 0,
      "resource": {
        "$type": "me.lqdev.resourcegraph.temp.defs#syndicationRef",
        "uri": "https://example.test/feed.xml",
        "format": "rss",
        "title": "Example feed"
      }
    }
  ]
}
```

Memberships are inline and ordered. The adapter copies each source
`CollectionItem.XmlUrl` exactly and uses the existing `Type` metadata to emit
an `rss` or `atom` syndication reference. Podcast feeds and YouTube channel
feeds remain ordinary syndication references. `HtmlUrl` is not fetched and is
not silently promoted to a scraped web-page resource.

The standalone project is not a package dependency of this site. The local
adapter is intentionally small and documents the compatible field names:
`$type`, `name`, optional `description`, `members`, `position`, `resource`,
and the `syndicationRef` envelope. Relationship, authorship, CID, and runtime
provenance fields are not invented here because they are not part of the
current draft bundle JSON contract.

## Safety and activation

`ResourceGraphStaging.useResourceGraphStaging` is `false` by default. With the
flag off, the normal build does not create Resource Graph files and makes no
network calls. When deliberately enabled, the build writes only deterministic
local staging files under:

```text
_public/api/data/atproto/resource-graph/
```

The directory contains the three draft bundles, a source-hash manifest, and a
conventional-OPML loss report. The source hash follows the existing
hash-and-write-if-changed pattern. The
`resourceGraphActivationCutoff` is forward-only; a pre-cutoff staging run
fails rather than backfilling a historical snapshot. The current collection
JSON has no per-membership authored timestamps, so the cutoff gates the
snapshot and does not invent dates.

No sync script consumes this directory yet. In particular, the static build
does not call `com.atproto.repo.putRecord`, delete records, authenticate, or
scrape pages. Any future publisher must retain the existing dry-run-first and
explicit `--commit` safety model.

## Conventional OPML loss report

Conventional OPML remains generated by the existing collection pipeline. Its
feed-reader profile cannot represent Resource Graph authorship, membership
relationships, CIDs, nested bundles, provenance, or live/frozen semantics.
The staging artifact writes these losses explicitly in
`conventional-opml-loss-report.json`, and
`test-scripts/test-resource-graph-staging.fsx` locks the report to a checked-in
fixture so a future exporter cannot hide the loss.

Run the focused contract test from the repository root:

```powershell
dotnet fsi test-scripts/test-resource-graph-staging.fsx
```
