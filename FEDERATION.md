# Federation

This document describes how `lqdev.me` federates, following [FEP-67ff](https://codeberg.org/fediverse/fep/src/branch/main/fep/67ff/fep-67ff.md) (Federation documentation).

`lqdev.me` is a single-user, static-first site. HTML is generated by an F# static site generator; ActivityPub endpoints are Azure Functions in [`api/`](api/) that serve build-time JSON and process a minimal inbox. There is no web UI for the Fediverse account — the site *is* the profile.

## Supported federation protocols and standards

- [ActivityPub](https://www.w3.org/TR/activitypub/) — server-to-server only. No client-to-server (C2S) API.
- [WebFinger](https://www.rfc-editor.org/rfc/rfc7033) — `/.well-known/webfinger`, with `/.well-known/host-meta` (XRD, `lrdd` template).
- [HTTP Signatures](https://datatracker.ietf.org/doc/html/draft-cavage-http-signatures) (cavage draft) — outgoing requests are signed with `rsa-sha256`; incoming inbox POSTs are verified. A `Digest` header is included on signed POSTs.
- [NodeInfo 2.1](https://nodeinfo.diaspora.software/) — `/.well-known/nodeinfo` → `/nodeinfo/2.1`.
- [Mastodon extensions](https://docs.joinmastodon.org/spec/activitypub/#extensions) — `toot:discoverable`, `toot:indexable`, `toot:featured`, `alsoKnownAs`, `PropertyValue` attachments.

## Actor

- Actor: `https://lqdev.me/api/activitypub/actor` (`Person`, `preferredUsername: lqdev`)
- Handle: `@lqdev@lqdev.me`
- `alsoKnownAs`: `https://toot.lqdev.tech/users/lqdev` (Mastodon mirror)
- `discoverable: true`, `indexable: false` — the account may appear in directories and profile search, but opts out of full-text post search.
- `manuallyApprovesFollowers: false` — follows are auto-accepted.
- `featured` collection: `https://lqdev.me/api/activitypub/featured` (pinned posts, built from `Data/pinned-posts.json`).

## Activities

### Outgoing (outbox / delivered to followers)

| Activity | Object | Source content |
|----------|--------|----------------|
| `Create` | `Article` | posts |
| `Create` | `Note` | notes, bookmarks, replies (`inReplyTo`), media, reviews |
| `Like` | remote URL | star responses |
| `Announce` | remote URL | reshare responses |
| `Accept` / `TentativeAccept` / `Reject` | `Event` | RSVP responses |

Activities are generated at build time and are immutable. The site does not send `Update` or `Delete` (content edits produce no federation events).

Delivery is push-based to follower inboxes via Azure Queue Storage after each deployment; only items published in the previous 24 hours are queued.

### Incoming (inbox)

| Activity | Handling |
|----------|----------|
| `Follow` | Stored in Table Storage; `Accept` delivered asynchronously. |
| `Undo { Follow }` | Follower removed. |
| Anything else | Acknowledged (202) and discarded. |

Replies, likes, and boosts of this site's content are **not** stored or displayed anywhere. This is deliberate: the site does not show third-party content. (Webmentions are received by an external endpoint and likewise not rendered.)

## Collections

| Collection | URL | Notes |
|------------|-----|-------|
| outbox | `/api/activitypub/outbox` | `OrderedCollection`, paginated 50/page (`?page=N`). |
| followers | `/api/activitypub/followers` | Public, regenerated from Table Storage at build. |
| following | `/api/activitypub/following` | Empty collection. |
| featured | `/api/activitypub/featured` | Pinned posts, inline objects. |

Individual activities dereference at `/api/activitypub/activities/{hash}`; the Note/Article object ID is the same URL with `#object`.

## Discovery and search

- `discoverable: true`, `indexable: false` (see above).
- The `fediverse:creator` meta tag is emitted on every page for Mastodon author attribution.
- Web crawler policy is in `/robots.txt` (AI-training bots are blocked).

## Content types and media

- `Accept: application/activity+json` or `application/ld+json; profile="https://www.w3.org/ns/activitystreams"` on all AP endpoints.
- Media are attached to `Note` objects as `Document` attachments (Mastodon/Pixelfed-compatible), not standalone `Image`/`Video` objects.
- Hashtags are emitted as `Hashtag` tags linking to `/tags/{tag}/`.

## Rate limits and blocking

No rate limits are applied beyond Azure Functions defaults. There is no instance block list; unwanted interactions are simply not stored.
